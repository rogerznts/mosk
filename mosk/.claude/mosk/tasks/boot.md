# boot

Analyze a consuming project and generate a compact context skill set for faster future work.

## Goal

Create a small amount of durable project context without exploding the number of generated skills.

## Workflow

### Phase 0 - Check CLAUDE.md

1. Check if `CLAUDE.md` exists in the project root, if exists update it with .claude/mosk/claude_boot.md file.
2. If it does **not** exist, create the base `CLAUDE.md` from .claude/mosk/claude_boot.md file.
3. Only proceed to Phase 1 after confirming `CLAUDE.md` is present.

### Phase 1 - Inspect the project

1. Read the directory structure up to 3 levels deep, excluding obvious dependency and VCS folders.
2. Read `CLAUDE.md` to understand any existing project instructions.
3. Read the main reference files that exist:
   - `README.md`
   - package and build manifests
   - primary config files
   - sample env files
4. Sample representative source files from the main layers that exist:
   - entrypoints or routes
   - services or use cases
   - models or repositories
   - frontend components, if any
   - tests

### Phase 2 - Generate base context skills

Create only these skills by default:

- `.claude/skills/ctx-project/SKILL.md`
- `.claude/skills/ctx-frontend/SKILL.md` only if frontend code exists

`ctx-project` should contain:
- system purpose
- stack
- architecture pattern
- folder conventions
- testing commands
- common workflows
- rules the AI should follow in this project

`ctx-frontend` should contain only:
- frontend stack
- component and styling conventions
- state and API call patterns
- frontend testing notes

### Phase 3 - Suggest additional context skills

Based on the project type and what was discovered in Phase 1, evaluate which additional context skills would be useful. Present each suggestion to the user and **wait for approval** before creating it.

Possible suggestions (evaluate relevance for the specific project):

- **ctx-coding-standards**: naming conventions, linting rules, code style, import ordering, file organization patterns actually found in the codebase.
- **ctx-testing**: test framework, how to run tests (unit, integration, e2e), coverage expectations, test file location patterns, fixtures and factories.
- **ctx-migrations**: how to create and run database migrations, ORM conventions, seed data, rollback procedures.
- **ctx-permissions**: authentication and authorization patterns, role system, middleware chains, access control conventions.
- **ctx-deploy**: deployment process, CI/CD pipeline, environment variables, staging vs production differences.
- **ctx-api**: API conventions, endpoint patterns, request/response contracts, pagination, error format.

Rules for this phase:
- Only suggest skills that are clearly supported by evidence found in the project.
- Present each suggestion with a one-line rationale explaining why it was detected as relevant.
- The user may accept all, some, or none.
- Do not create any skill the user did not approve.

### Phase 4 - Update CLAUDE.md

Update the project's `CLAUDE.md` file to include a context skills section so that all MOSK agents can discover and use the generated context:

1. If a `## Context Skills` section already exists, update it.
2. Otherwise, append the section below.

Add this section:

```markdown
## Context Skills

The following context skills were generated by `/mosk-boot` and are available in `.claude/skills/`:

{list each generated skill folder with a one-line description of its content}

MOSK agents automatically discover and load relevant context skills before executing tasks. Re-run `/mosk-boot` to regenerate them if the project structure changes significantly.
```

### Phase 5 - Report

Report:
- files created or updated (including `CLAUDE.md`)
- stack detected
- additional skills suggested vs. approved
- areas that were not identified cleanly

## Rules

- Do not invent project conventions. Only document what is actually found.
- Keep each generated skill short and prescriptive.
- Prefer one strong `ctx-project` skill over many narrow context files.
- Never create additional context skills without explicit user approval.
- Always explain why each additional skill is being suggested.
